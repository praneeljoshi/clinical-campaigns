# Clinical Campaigns - Claude Context & Best Practices

> This file provides context for AI assistants (Claude) working on this codebase to ensure consistency, safety, and adherence to best practices.

## Project Overview

**Clinical Campaigns** is a HIPAA-compliant platform for deploying AI-powered voice outreach campaigns to patients who have not utilized preventive care screening benefits (breast, cervical, and colorectal cancer screenings).

**Critical Context**: This system handles Protected Health Information (PHI) and must maintain strict compliance with healthcare regulations.

---

## Core Principles

### 1. Safety & Compliance First

**ALWAYS prioritize patient safety and regulatory compliance over feature velocity.**

- **HIPAA Compliance**: Every feature that touches patient data must include privacy safeguards
- **Guardrails**: Voice AI interactions require multi-layer safety controls
- **Audit Trails**: All PHI access must be logged with actor, action, timestamp, and outcome
- **Data Minimization**: Only share the minimum necessary PHI with external services (voice providers)

### 2. Type Safety

**Leverage TypeScript's type system to prevent runtime errors.**

- Use strict TypeScript configuration (`strict: true`)
- Prefer interfaces for data contracts, types for unions/intersections
- Avoid `any` type; use `unknown` if type is truly unknown, then narrow with type guards
- Define schemas for external API payloads and validate at runtime (Zod, io-ts)

### 3. Security by Design

**Assume breach at every layer.**

- Encrypt PHI at rest (field-level encryption for sensitive fields)
- Encrypt in transit (TLS 1.3 minimum)
- Never log PHI in plain text (use hashed patient IDs in logs)
- Implement defense in depth: WAF → API Gateway → Application Auth → Database encryption
- Use parameterized queries to prevent SQL injection
- Sanitize all user inputs to prevent XSS

### 4. Observability

**You can't fix what you can't see.**

- Comprehensive logging with structured JSON logs
- Instrument critical paths with metrics (latency, error rate, throughput)
- Distributed tracing for cross-service requests
- Real-time alerting for critical failures (guardrail violations, PHI exposure risks)

#### Code Style
```typescript
// GOOD: Explicit return types, clear error handling
async function initiateCall(
  patientId: string,
  campaignId: string
): Promise<CallSession> {
  try {
    const session = await this.sessionManager.createSession(patientId, campaignId)
    const decoratedSession = await this.decorator.decorate(session)

    // Validate guardrails before initiating call
    const guardrailCheck = await this.guardrails.preCallValidation(decoratedSession)
    if (!guardrailCheck.passed) {
      throw new GuardrailViolationError(guardrailCheck.violations)
    }

    return await this.voiceProvider.initiateCall(decoratedSession)
  } catch (error) {
    logger.error('Failed to initiate call', { patientId, campaignId, error })
    throw new CallInitiationError('Unable to start call', { cause: error })
  }
}

// BAD: Implicit returns, poor error handling, no types
async function initiateCall(patientId, campaignId) {
  const session = await createSession(patientId, campaignId)
  return voiceProvider.call(session) // What if this fails?
}
```

from typing import List, Optional
from pydantic import BaseModel

class PatientScore(BaseModel):
    patient_id: str
    eligibility_score: float
    risk_factors: List[str]

async def score_patients(
    patients: List[Patient],
    screening_type: str
) -> List[PatientScore]:
    """Calculate eligibility scores for a cohort of patients.

    Args:
        patients: List of patient records
        screening_type: Type of screening (mammogram, colonoscopy, pap_smear)

    Returns:
        List of scored patients sorted by priority

    Raises:
        ValidationError: If patient data is incomplete
    """
    scored = []
    for patient in patients:
        try:
            score = await self._calculate_score(patient, screening_type)
            scored.append(score)
        except ValidationError as e:
            logger.warning(f"Skipping patient {patient.id}: {e}")
            continue

    return sorted(scored, key=lambda x: x.eligibility_score, reverse=True)

## Security Best Practices

### 1. PHI Handling

**Protected Health Information (PHI) includes**: Name, phone number, email, medical history, screening results, appointment details.

#### DO ✅
```typescript
// Hash patient IDs in logs
logger.info('Call initiated', {
  patientIdHash: hashPatientId(patientId),
  campaignId: campaignId
})

// Encrypt PHI before database storage
const encryptedData = await encryptionService.encryptPHI({
  firstName: patient.firstName,
  phoneNumber: patient.phoneNumber
})

// Minimize PHI sent to voice provider
const voiceContext = {
  patient_first_name: patient.firstName, // OK: Needed for personalization
  screening_type: campaign.screeningType,
  // DO NOT send: SSN, full medical history, etc.
}
```

#### DON'T ❌
```typescript
// NEVER log PHI
logger.info('Patient data', { patient }) // ❌ Contains PHI

// NEVER send unnecessary PHI to external services
const voiceContext = {
  ...patient, // ❌ Sends entire patient object including SSN, etc.
  medicalHistory: patient.fullHistory // ❌ Not needed by voice agent
}

// NEVER store PHI in plain text
await db.patients.create({
  phone: patient.phoneNumber // ❌ Should be encrypted
})
```

### 2. Authentication & Authorization

```typescript
// Implement role-based access control
enum Role {
  ADMIN = 'admin',
  CAMPAIGN_MANAGER = 'campaign_manager',
  VIEWER = 'viewer'
}

interface User {
  id: string
  role: Role
  permissions: Permission[]
}

// Check permissions before sensitive operations
function requirePermission(permission: Permission) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!req.user.permissions.includes(permission)) {
      throw new ForbiddenError('Insufficient permissions')
    }
    next()
  }
}

// Usage
app.post('/campaigns',
  authenticate,
  requirePermission(Permission.CREATE_CAMPAIGN),
  createCampaignHandler
)
```

## Guardrail Development

When implementing or modifying guardrails:

### 1. Classify Severity

```typescript
enum GuardrailSeverity {
  LOW = 'LOW',           // Log and continue
  MEDIUM = 'MEDIUM',     // Warn and redirect conversation
  HIGH = 'HIGH',         // Escalate to human
  CRITICAL = 'CRITICAL'  // Terminate call immediately
}
```

### 2. Define Clear Actions

Each guardrail must specify what happens on violation:
- **ALLOW**: Continue normally
- **WARN**: Log violation, allow conversation to continue
- **REDIRECT**: Steer conversation back to allowed topics
- **ESCALATE**: Transfer to human operator
- **TERMINATE**: End call immediately

### 3. Test Thoroughly

```typescript
describe('ComplianceGuardrail', () => {
  it('should block medical diagnosis attempts', async () => {
    const context = {
      latestUtterance: "Can you tell me if I have cancer?"
    }

    const result = await guardrail.evaluate(context)

    expect(result.passed).toBe(false)
    expect(result.action).toBe('REDIRECT')
    expect(result.redirectScript).toContain('healthcare provider')
  })

  it('should allow scheduling questions', async () => {
    const context = {
      latestUtterance: "What times are available for my screening?"
    }

    const result = await guardrail.evaluate(context)

    expect(result.passed).toBe(true)
  })
})
```

## Voice AI Integration Patterns

### Provider Abstraction

Always code against interfaces, not concrete implementations:

```typescript
// GOOD: Provider-agnostic
interface VoiceProvider {
  initiateCall(request: CallRequest): Promise<CallSession>
  updateContext(sessionId: string, context: any): Promise<void>
  terminateCall(sessionId: string): Promise<void>
}

class CallService {
  constructor(private provider: VoiceProvider) {}

  async startCall(patient: Patient) {
    return this.provider.initiateCall({ ... })
  }
}

// Can swap providers easily
const service = new CallService(new VapiProvider())
// or
const service = new CallService(new ElevenLabsProvider())

// BAD: Tightly coupled to Vapi
class CallService {
  async startCall(patient: Patient) {
    return vapiClient.calls.create({ ... }) // Hard to swap providers
  }
}
```

### Context Enrichment

Always sanitize and minimize data sent to voice providers:

```typescript
class VoiceContextBuilder {
  buildContext(patient: Patient, campaign: Campaign): VoiceAgentContext {
    // Only include what's necessary for the conversation
    return {
      // Personalization (minimal)
      patient_first_name: patient.firstName,

      // Clinical (sanitized)
      screening_type: campaign.screeningType,
      is_overdue: this.isOverdue(patient.lastScreening),

      // DO NOT include: SSN, full address, detailed medical history, etc.
    }
  }

  private isOverdue(lastScreening?: Date): boolean {
    if (!lastScreening) return true
    const monthsSince = this.monthsBetween(lastScreening, new Date())
    return monthsSince > 12 // Simplified logic
  }
}
```

## Common Pitfalls to Avoid

### 1. Logging PHI

❌ **NEVER**:
```typescript
logger.info('Processing patient', { patient })
console.log('Phone number:', patient.phoneNumber)
```

✅ **ALWAYS**:
```typescript
logger.info('Processing patient', {
  patientIdHash: hashPatientId(patient.id),
  campaignId: campaign.id
})
```

### 2. Insufficient Error Handling

❌ **NEVER**:
```typescript
const patient = await db.patients.findOne(id)
return patient.phoneNumber // What if patient is null?
```

✅ **ALWAYS**:
```typescript
const patient = await db.patients.findOne(id)
if (!patient) {
  throw new NotFoundError(`Patient ${hashPatientId(id)} not found`)
}
return patient.phoneNumber
```

### 3. Ignoring Guardrail Violations

❌ **NEVER**:
```typescript
const result = await guardrails.evaluate(context)
// Continue anyway, ignore result
await sendMessage(context.message)
```

✅ **ALWAYS**:
```typescript
const result = await guardrails.evaluate(context)
if (!result.passed) {
  logger.error('Guardrail violation', { violation: result })
  if (result.severity === 'CRITICAL') {
    await terminateCall(sessionId)
  }
  return // Don't proceed
}
await sendMessage(context.message)
```

### 4. Hardcoding Configuration

❌ **NEVER**:
```typescript
const apiKey = 'vapi_sk_1234567890' // Hardcoded secret
const dbUrl = 'postgresql://localhost:5432/prod' // Hardcoded URL
```

✅ **ALWAYS**:
```typescript
const apiKey = process.env.VAPI_API_KEY
if (!apiKey) {
  throw new Error('VAPI_API_KEY environment variable not set')
}

const dbUrl = process.env.DATABASE_URL
```

## Performance Guidelines

### Database Queries

1. **Always use indexes** on frequently queried fields (patient_id, campaign_id, created_at)
2. **Paginate** large result sets (use cursor-based pagination for real-time data)
3. **Use connection pooling** (max 20 connections for most workloads)

```typescript
// GOOD: Indexed query with pagination
const patients = await db.patients.findMany({
  where: { campaignId: campaignId },
  take: 100,
  skip: offset,
  orderBy: { eligibilityScore: 'desc' }
})

// BAD: Full table scan
const patients = await db.patients.findMany()
const filtered = patients.filter(p => p.campaignId === campaignId)
```

### Caching Strategy

```typescript
// Cache expensive computations
class PatientEligibilityService {
  private cache: Redis

  async getEligibilityScore(patientId: string): Promise<number> {
    const cached = await this.cache.get(`eligibility:${patientId}`)
    if (cached) return parseFloat(cached)

    const score = await this.calculateScore(patientId)
    await this.cache.setex(`eligibility:${patientId}`, 3600, score)
    return score
  }
}
```

## When to Ask for Clarification

If you're working on this codebase and encounter any of these situations, **STOP and ask**:

1. **Unclear PHI handling**: Not sure if a field contains PHI? Ask before proceeding.
2. **Guardrail edge case**: Found a scenario not covered by existing guardrails? Discuss before implementing.
3. **External service integration**: Adding a new third-party service? Confirm security review is complete.
4. **Database schema changes**: Modifying patient or campaign tables? Verify migration strategy.
5. **Voice provider changes**: Switching or adding voice providers? Coordinate with team.
